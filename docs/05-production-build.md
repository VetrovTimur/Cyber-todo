# Продакшн-сборка (`npm run build`)

Команда `npm run build` создает полностью готовый к деплою проект в папке `build/`. Этот процесс сильно отличается от dev-режима.

## 1. Хэширование файлов (Cache Busting)
Чтобы браузеры пользователей всегда загружали свежие версии стилей и скриптов, сборка добавляет к их именам уникальный хэш (например, `style-a1b2c3d4.css` и `main-e5f6g7h8.js`).
*   При сборке создается файл `rev-manifest.json`, который хранит соответствие старых имен новым.
*   Плагин `gulp-rev-rewrite` автоматически читает этот манифест и подменяет ссылки в HTML-файлах на новые (с хэшем).

## 2. Проверка качества кода
Перед финальной сборкой запускаются строгие проверки. Если найдутся ошибки, сборка прервется:
*   **ESLint** — проверяет JS-код.
*   **Stylelint** — проверяет SCSS.
*   **html-validate** — проверяет готовый HTML на валидность (правильность закрытия тегов, атрибутов и т.д.).

## 3. SEO и Служебные файлы
Сборка автоматически генерирует важные для поисковиков файлы:
*   **Sitemap:** Создается карта сайта `sitemap.xml` на основе всех HTML-страниц. Приоритеты страниц можно настроить в `config.js` (блок `site.priorities`).
*   **Robots.txt:** Создается автоматически с указанием ссылки на sitemap.
*   **Мета-теги:** В `<head>` автоматически вставляются Open Graph (для соцсетей) и Schema.org (микроразметка для поисковиков). Настройки находятся в `config.js`.
*   **Critical CSS:** Критические стили вырезаются из общего файла и инлайнятся в `<head>` (как было описано в файле про стили).

## 4. Анализ размеров
После сборки в консоли выводится отчет о размерах итоговых файлов (HTML, CSS, JS) с учетом gzip-сжатия.
*   Для детального анализа JS-бандла можно запустить `npm run analyze`. Это создаст интерактивную HTML-карту (`analyze.html`), где будет видно, какие библиотеки занимают больше всего места.
