# Стили и скрипты

## 1. Работа со стилями (SCSS)
Главный файл стилей находится по пути `src/scss/style.scss`. Все остальные SCSS-файлы (переменные, миксины, компоненты) должны импортироваться в него.

*   **В dev-режиме** (`npm run dev`): стили компилируются, добавляются вендорные префиксы (autoprefixer) и создаются sourcemaps для удобной отладки в браузере.
*   **В prod-режиме** (`npm run build`): стили минифицируются, сжимаются и получают хэш в названии файла (например, `style-a1b2c3d4.css`) для сброса кэша браузера.

## 2. Critical CSS (Критический CSS)
В сборке настроен плагин для извлечения критического CSS. По умолчанию включен **ручной режим** (`mode: 'manual'` в `config.js`).

Чтобы стили попали в критический CSS, их нужно обернуть специальными комментариями в SCSS-файлах:

```scss
/*! CRITICAL:common:START */
.header { display: flex; }
/*! CRITICAL:common:END */

/*! CRITICAL:index:START */
.hero { padding: 50px; }
/*! CRITICAL:index:END */
```

**Как это работает при сборке (`npm run build`):**
*   Блок `common` попадет на **все** страницы.
*   Блок `index` попадет только на страницу `index.html`.
*   Сборка вырежет эти стили из общего файла `style.css` и вставит их прямо в `<head>` (в место маркера `<!-- critical-css -->`).

## 3. Работа со скриптами (JS)
Точка входа для JavaScript — файл `src/js/main.js`. Сборщик использует **esbuild**, который поддерживает современный синтаксис и модули (import/export).

*   **В dev-режиме**: скрипты собираются в один бандл (без минификации) и создаются sourcemaps.
*   **В prod-режиме**: код минифицируется, проходит проверку линтером (ESLint) и получает хэш в названии.

**Как подключать скрипты в HTML:**
```html
<script src="js/main.js"></script>
```
*(В продакшене ссылка автоматически заменится на файл с хэшем).*

## 4. Линтеры
В продакшн-сборке строго проверяется качество кода. Если есть ошибки, сборка упадет.
*   `stylelint` — проверяет SCSS (настройки в `.stylelintrc.json`).
*   `eslint` — проверяет JS (настройки в `eslint.config.js`).
